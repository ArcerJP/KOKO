# 費用と作業対効果の比較

現在の要件と採用構成を確認し、`docs/product/cost-policy.md`を読んでから評価します。このSkillは比較の手順であり、サービス作成・課金・削除を許可するものではありません。

## 比較の順序

1. 変えない要件を先に特定する。KOKOでは認証配信、公開前の必須AI判定、原本保持などを費用だけで緩和しない。候補が要件に反する場合は、変更点とリスクを示して採用前に質問する。
2. 現構成と候補について公式料金・制限・請求条件を実行時点で確認し、URLと確認日を残す。無料枠、最低購入枠、丸め、保存の最低期間、取得・操作・転送料、地域・通貨・税・プレビュー条件を区別する。
3. 同じ期間・負荷条件で比較する。実測、ユーザー提供、仮定、未取得を分け、低/標準/高負荷の量と式を示す。未知の利用量を実績とせず、安全な読取りと明示した範囲試算で調査を進める。本人しか把握できない重要な予算・利用条件はまとめて質問する。
4. KOKOの要求経路で積算する。動画長だけでなく、source/clipの二重保存、segment/MP4 Range、先読み、再取得、cache hit、認証/DB、処理・AIの再試行を含める。認可後の内部cacheと端末cacheを混同しない。
5. 現状維持も選択肢に含め、各案の節約対象、金額または範囲、利点、欠点、実装/保守/移行工数、失効・互換性・再処理リスクを示す。工数単価が未定なら金額へ架空換算せず、時間を併記する。
6. 推奨と代替案、採用条件・未検証事項を示す。要件・安全性を維持する通常の技術的改善は[自律進行の区分](../../../AGENTS.md#作業進行と承認境界)で判断・記録する。予算や通知閾値の決定、有料操作・実データ削除・外部設定変更は本人の個別確認へ分離し、包括的な続行指示で実行しない。比較案の採用と実際の課金操作の許可を混同しない。

## 記録・検証

調査の証拠と計算は現在の`work/notebook/<task-id>/research/`へ、採用した方針は対応するdocs/正本へ記録し、AIの技術的判断と本人の個別承認を区別する。比較表の推論を検証済みの請求削減と表現しない。料金やベンダーの数値をこのSkillへ固定して複製しない。

本番前の負荷試験後に再計算し、採用した場合は合意した品質・安全性を維持しているか確認する。請求/使用量を確認できない場合はその限界と人間が確認する項目を示す。秘密、個人の請求明細、トークンを公開記録へ含めず、予算通知が支出を自動停止するとは仮定しない。
